# Лабораторная работа № 3
Тема работы — матричные преобразования и построение многообъектных сцен в OpenGL. В лабораторной используются перенос, поворот, масштабирование, стек матриц, ортографическая и перспективная проекции.

Вариант: **3**.

Методические указания находятся в файле [ЛР_3.pdf](./ЛР_3.pdf).

## Задания

### Задание 1 — модель атома

Основа: листинг 1 из методических указаний.

Требование варианта 3: заменить круговые орбиты электронов на произвольные замкнутые траектории.

В программе используются три эллиптические траектории с разными полуосями. Электроны остаются в исходных плоскостях, а остальные параметры примера не изменяются.

Файл: [list1.cpp](./list1.cpp).

### Задание 2 — многогранник

Основа: листинги 2 и 3 из методических указаний.

Необходимо изобразить фигуру № 3 из раздела «Варианты заданий» на странице 97 методички. Внутренние и внешние грани должны иметь разные цвета. Допускается назначить отдельный цвет каждой внешней грани. Также необходимо изменить цвет фона относительно исходного примера.

При реализации следует сохранить два способа проецирования, показанные в исходных листингах:

- ортографическую проекцию из листинга 2
- перспективную проекцию из листинга 3

Планируемые файлы: `list2.cpp` и `list3.cpp`.

### Задание 3 — система Земля–Луна

Основа: листинг 4 из методических указаний.

Требование варианта 3: добавить одну планету без спутника в плоскости и на траектории системы Земля–Луна.

Новая планета должна двигаться вокруг Солнца по той же орбитальной плоскости. Существующие Солнце, Земля и Луна не изменяются, если это не требуется для размещения нового объекта.

Планируемый файл: `list4.cpp`.

### Задание 4 — вращающийся тор

Основа: листинг 5 из методических указаний.

Требование варианта 3: закрасить тор и изменить направление его вращения.

Геометрия сцены и остальные параметры исходного примера должны быть сохранены.

Это задание обязательно только при выполнении лабораторной работы на оценку «отлично».

Планируемый файл: `list5.cpp`.

### Задание 5 — сцена с множеством объектов

Основа: листинг 7 из методических указаний.

Требование варианта 3: уменьшить размеры пространства и расположить в нём 40 сфер произвольного цвета на разных уровнях по оси `z`.

Сферы должны находиться внутри уменьшенного пространства и различаться положением. Остальную логику исходной сцены изменять не требуется.

Это задание обязательно только при выполнении лабораторной работы на оценку «отлично».

Планируемый файл: `list7.cpp`.

## Сборка и запуск из терминала

Проект собирается через CMake с компилятором MinGW так же, как предыдущие лабораторные работы. CMake подключает локальный `glut.h`, использует `glut32.dll` из каталога `lab1` и автоматически копирует библиотеку рядом с программой.

Перейти в каталог `lab3`, настроить проект, собрать и запустить первый листинг:

```text
cd /d D:\github\Computer-graphics\lab3
cmake --preset mingw-debug
cmake --build --preset mingw-debug
.\build\list1.exe
```

Повторно выполнять первую команду после изменения только исходного кода необязательно. Достаточно пересобрать и запустить программу:

```text
cmake --build --preset mingw-debug
.\build\list1.exe
```

## Важные моменты

- за основу каждого задания берётся соответствующий листинг из методички
- в исходный код вносятся только изменения, предусмотренные вариантом 3 и общими требованиями
- перед преобразованием отдельного объекта текущая матрица сохраняется через `glPushMatrix()`
- после построения отдельного объекта матрица восстанавливается через `glPopMatrix()`
- порядок вызовов `glTranslatef`, `glRotatef` и `glScalef` влияет на итоговое положение объекта
- перед настройкой проекции необходимо выбрать `GL_PROJECTION` и сбросить матрицу через `glLoadIdentity()`
- перед построением сцены необходимо вернуться к `GL_MODELVIEW`
- при изменении размеров окна нужно учитывать отношение ширины к высоте, чтобы фигуры не искажались
- для корректного отображения трёхмерных объектов должен быть включён буфер глубины
- анимация выполняется через функцию таймера GLUT и вызов `glutPostRedisplay()`
- для плавного вывода кадров используется двойная буферизация и `glutSwapBuffers()`
- дополнительные комментарии в коде, относящиеся к варинту, а не к методичке, пишутся с маленькой буквы и не заканчиваются точкой
- каждая функция должна иметь подробный комментарий о своём назначении
- неочевидные вычисления и матричные преобразования должны сопровождаться пояснениями
